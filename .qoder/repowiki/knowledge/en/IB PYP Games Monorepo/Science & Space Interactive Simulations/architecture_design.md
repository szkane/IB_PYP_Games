Two coexisting patterns live side-by-side:
- Standalone single-file experiments (`g1_*.html`) — self-contained HTML pages that inline Three.js r128 and MediaPipe Hands via CDN script tags, each implementing its own camera, render loop, and state machine (e.g. `g1_bike_gear.html` uses Canvas 2D; the blueball/dragonball pages use custom vertex/fragment shaders on `THREE.Points`).
- The `gesture-cosmos/` sub-project — an ES-module hub (`main.js`) that owns one shared `THREE.Scene`, `PerspectiveCamera`, `WebGLRenderer`, and `TextureLoader`, then composes four core classes from `core/`: `HandEngine` (MediaPipe Hands wrapper loaded from globals), `GestureRouter` (debounced open-palm/fist + depth-to-scale + palm-X-to-Y-rotation state machine emitting `{handDepth, rotateY, fist, openness}` commands), `CameraRig` (OrbitControls-driven camera), and `SceneHost` (lifecycle manager). Six scene modules under `scenes/` are registered dynamically via `import()` keyed by name (`solar-system`, `neon-planets`, `galaxy-spiral`, `crystal-galaxy`, `milky-way`, `shape-motion`) and must export `{ name, init(ctx), update(dt, cmd), dispose() }`; `ctx` is injected by `SceneHost.setContext`. The main `requestAnimationFrame` loop drives `GestureRouter.process → CameraRig.applyCommand → SceneHost.update(dt, cmd)` each frame. An `_archive/` directory holds older abandoned prototypes.
Dependency direction: `main.js` → `core/*` → `scenes/*`; scenes depend only on the stable `ctx` contract and never import each other.
